Kilo Local UI packages its launcher together with an official pinned Kilo binary so end users can download one archive and run it directly.

## Version pins

Two repository files make the relationship explicit:

- `VERSION` tracks the Kilo Local UI release version;
- `KILO_VERSION` tracks the Kilo runtime version to bundle.

The current source pins Kilo `7.6.2`.

## Release workflow

The release workflow is designed to:

1. read the pinned Kilo version;
2. obtain the matching official Kilo release asset;
3. run tests;
4. cross-compile the Go launcher;
5. package the launcher and Kilo for supported platforms;
6. publish archives and checksum information for an intentional `v*` release tag.

## Why pin the runtime

Pinning makes the browser/API contract reviewable and repeatable. A Kilo upgrade is not treated as an invisible dependency update: the adapter and protocol contract should be reviewed against the new upstream version first.
