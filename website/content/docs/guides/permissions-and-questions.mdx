Coding agents sometimes need explicit approval before performing an action or need an answer before they can continue. Kilo Local UI surfaces those requests from the local Kilo session.

## Permission replies

The current Kilo contract supports three replies:

- `once` — allow this request once;
- `always` — allow and persist the applicable permission according to Kilo's rules;
- `reject` — deny the request.

A request may include an action, affected resources, metadata, and tool-source information. Read the request before approving it, especially when a tool can execute commands or modify files.

## Questions

When Kilo raises an interactive question, the browser UI can present it and send the answer back to the current session. This keeps interactive agent workflows usable without returning to an IDE.

## Security responsibility

The local-only network boundary prevents remote exposure by default, but it does not make every agent action safe. The most important security boundary remains the permissions you grant to Kilo for the project you opened.
