Coding agents sometimes need explicit approval before performing an action or need an answer before they can continue. Kilo Local UI surfaces those requests from the selected local project and filters them to the active session.

## Permission replies

The current Kilo product contract supports three replies:

- `once` — allow this request once;
- `always` — allow it and persist the applicable rule according to Kilo's permission behavior;
- `reject` — deny the request.

Production permission requests can include fields such as the permission name, matching patterns, metadata, rules that can be saved as always allowed, and optional tool-source information.

Read the request before approving it, especially when a tool can execute commands or modify files.

## Questions

Kilo's product question flow can present option lists, single or multiple selection, optional custom answers, and an optional default selection. The browser adapter sends answers or rejections back to the matching Kilo request.

## Security responsibility

The local-only network boundary prevents remote exposure by default, but it does not make every agent action safe. The most important security boundary remains the permissions you grant to Kilo for the project you opened.
