## Project routing

Project-scoped requests carry the selected directory explicitly as Kilo's `directory` query parameter. At the proxy boundary the launcher also injects `x-kilo-directory`.

This dual routing is deliberate:

- it matches the product-facing Kilo client behavior for the pinned runtime;
- it prevents the Kilo server's own working directory from silently becoming the active project;
- changing projects also changes the context for agents, providers, sessions, messages, permissions, questions, events, and filesystem tools.

The browser still does not need direct filesystem privileges or Kilo server credentials.

## Sessions

Kilo remains the source of truth for session state. On Kilo `7.6.2`, Kilo Local UI follows the product session routes used by the official client for its primary coding flow, including session list/create, status, messages, asynchronous prompts, and abort.

## Sending a prompt

The production coding path sends prompts with Kilo's asynchronous prompt operation. Agent and model are supplied explicitly with the prompt. Conceptually:

```json
{
  "agent": "code",
  "model": {
    "providerID": "kilo",
    "modelID": "kilo-auto/free"
  },
  "parts": [
    { "type": "text", "text": "..." }
  ]
}
```

Prompt acceptance and model execution are separate stages. The UI observes session status, messages, and events rather than treating the prompt HTTP response as the assistant's final answer.

## Messages

For the product API in the pinned runtime, conversation messages use Kilo's `info + parts` representation. Parts can include text, reasoning, tools, subtasks, and file-related content.

Tool activity can move through pending, running, completed, and error states. The projected message list remains the reconnect-safe rendering source of truth.

## Live activity and fallback polling

Kilo Local UI can consume Kilo's project-scoped global SSE stream for responsive updates. It also polls session status/messages after a prompt as a conservative fallback. Transient SSE updates improve presentation, but durable conversation rendering comes from the projected session messages.
