TL Studio یک **Application محلی واحد** با Browser Assetهای Embedded و Coding-Agent Core بومی است.

نسخهٔ عمومی فعلی v0.5.0 است. خط توسعهٔ v0.6.0-alpha.1 مرز Provider را با Account Integration گسترش می‌دهد، بدون اینکه معماری Agent تغییر کند.

~~~text
Browser Workspace
        │ Same Local Control Origin
        ▼
TL Studio Go Launcher / Local Core
  ├─ Workspace + Project Filesystem
  ├─ Project Search
  ├─ Terminal / Process Manager
  ├─ Preview Manager
  ├─ Provider Registry + Model Discovery
  ├─ Credential Vault
  ├─ Provider Account Adapters
  ├─ Session Domain + Persistence
  ├─ Question Manager
  ├─ Permission Engine
  ├─ Semantic Event Bus
  ├─ Tool Registry + Tool Executor
  ├─ Plugin Manager + MCP Clients
  └─ Native Agent + Direct Model Clients
        │
        ├─ Configured Provider Endpoints
        └─ Enabled Local MCP Processes

Previewed Project Content
        └────────► Separate Loopback Origin
~~~

## مدل Startup

در Startup عادی:

1. Project انتخاب‌شده Resolve می‌شود؛
2. Application State مربوط به TL Studio ساخته می‌شود؛
3. Product Serviceها Initialize می‌شوند؛
4. Control Server فقط روی Loopback Bind می‌شود؛
5. مگر اینکه حالت no-browser انتخاب شده باشد، Browser باز می‌شود.

Browser مستقیماً با Local Product Domainهای متعلق به TL Studio ارتباط دارد.

## مرز Browser

Surfaceهای مهم Browser شامل این مسیرها هستند:

~~~text
/local/status
/local/health
/local/project
/local/providers/*
/local/provider-accounts*
/local/sessions*
/local/questions*
/local/permissions*
/local/events
/local/plugins*
/local/tools
/local/search
/local/process*
/local/preview*
~~~

Browser Source با Strict TypeScript در cmd/launcher/ui قرار دارد و با esbuild Bundle می‌شود. Monaco و Workerهای آن هم Local Bundle هستند.

## Native Agent

مسیر Agent متعلق به خود TL Studio است:

~~~text
Browser Session Run
→ Session Domain
→ Native Agent
→ Selected Provider
→ Model Response
→ Optional Tool Call
→ Permission / Question when needed
→ Tool Executor or MCP Plugin
→ Structured Tool Result
→ Provider Continuation
→ Final Response
→ Session Persistence + Event Bus
~~~

Provider Protocol یا Capability پشتیبانی‌نشده Error صریح می‌دهد.

## Session، Question، Permission و Event

ساخت و انتخاب Session، Rename/Delete، Run/Abort، Status، Message، Activity، Usage Metadata، Changes و Persistence همگی در اختیار TL Studio هستند.

Tool مربوط به interaction.question، Agent را Pause می‌کند و یک Question در Scope همان Session ثبت می‌کند.

Permission Request و Ruleهای Project-scoped هم در Permission Engine نگهداری می‌شوند.

هر دو Domain از Local Event Bus، Event معنایی تولید می‌کنند.

## Provider و Credential

Provider Registry مالک Provider Definition، Modelهای Configure‌شده، Model Discovery، Catalog Cache و Direct Model Execution است.

Credentialها جداگانه در Credential Vault نگهداری می‌شوند و وارد providers.json یا Browser Storage نمی‌شوند.

### Provider Account Domain

در Development v0.6، Provider Account Adapter برای این سرویس‌ها پیاده‌سازی شده است:

- OpenRouter؛
- Hugging Face؛
- Google / Gemini؛
- ChatGPT / Codex.

Lifecycle عمومی شامل Status، شروع/تکمیل Login، Polling در صورت نیاز، Cancellation، Refresh، Credential Resolution، Model Discovery و Disconnect است.

Credential دستی API و Credential حسابی که TL Studio مدیریت می‌کند در Slotهای جداگانه نگهداری می‌شوند.

Browser فقط Account State معنایی و Login Instruction امن را دریافت می‌کند. OAuth Code، PKCE Verifier، Access Token، Refresh Token، API Key، Cookie و Client Secret وارد Browser State نمی‌شوند. برای ChatGPT، Client رسمی OpenAI Codex، OAuth Token Store را داخل CODEX_HOME ایزولهٔ مخصوص TL Studio نگه می‌دارد و TL Studio آن Tokenهای خام را نمی‌خواند یا Serialize نمی‌کند.

### Provider Bridge مربوط به ChatGPT / Codex

Login مربوط به ChatGPT از Flow رسمی account/login/start در Codex و Catalog رسمی model/list استفاده می‌کند.

Model Turn مبتنی بر پلن ChatGPT، Codex CLI رسمی را به‌صورت Ephemeral و از Working Directory موقت و خالی اجرا می‌کند. User/Project Codex Config و Ruleها Ignore می‌شوند، Sandbox فقط‌خواندنی است، Approval Policy روی never قرار دارد و Web Search غیرفعال است.

خروجی ساختاریافته به Assistant Text یا TL Studio Tool Call تبدیل می‌شود. Session State، Tool Execution، Permission، تغییرات پروژه، Persistence و Eventهای معنایی همچنان در اختیار TL Studio هستند.

### Loopback دسکتاپ Gemini

هر Sign-in مربوط به Gemini یک HTTP Listener موقت فقط روی این آدرس می‌سازد:

~~~text
127.0.0.1:<random-port>
~~~

Callback مقدار OAuth state را Validate می‌کند و بعد از Completion، Cancellation یا Expiry بسته می‌شود.

## Tool و Plugins/MCP

Toolهای داخلی شامل فایل‌های پروژه، Search، Terminal Command و Interactive Question هستند.

MCP Plugin فعال از نوع stdio می‌تواند Dynamic Tool اضافه کند. Plugin Tool قبل از اجرا وارد همان Tool Registry و Permission System می‌شود.

## Preview Isolation

Preview یک Local Trust Boundary جداست.

Static/File Content روی Loopback Origin جدا از Control Server سرو می‌شود و Dev Server Preview فقط Loopback URL را می‌پذیرد.

## State و Storage

Product State در Local Application State خود TL Studio نگهداری می‌شود؛ از جمله Provider Definition، Credential، Session، Permission Rule، Plugin Config/Secret، Model Catalog Cache، Provider Account Setup و Preferenceها.

Secretها از JSON Config معمولی جدا می‌مانند.

## قانون Zero-infrastructure

TL Studio برای استفادهٔ معمول به Application Backend، Database، Telemetry Collector، Model Proxy یا Hosted Workspace متعلق به پروژه نیاز ندارد.

Network Traffic از Configuration صریح User مثل Model Provider یا MCP Process ایجاد می‌شود.
