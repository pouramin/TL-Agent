TL Agent جزئیات Runtime را پشت یک Adapter Boundary نگه می‌دارد. Implementation بالادستی فعلی **Kilo Code 7.6.2** است؛ با این حال TL Agent محصولی مستقل است و Workflow عادی کاربر به شناختن یا کار مستقیم با آن Runtime وابسته نیست.

## Compatibility Contract

نسخه Runtime همراه برنامه Pin می‌شود و CI قرارداد Product-facing مربوط به Agent، Provider، Session، Status، Message، Async Prompt، Global Event، Permission، Question و Device Authorization را تست می‌کند.

## Adapter Boundary

فراخوانی‌های Browser به Runtime داخل یک Adapter اختصاصی در `cmd/launcher/web/` متمرکز شده‌اند. بخش‌های UI نباید Endpointهای Runtime را مستقیم بسازند. این مرزبندی Upgrade Runtime را قابل بررسی و تست نگه می‌دارد.

## قانون Upgrade

قبل از تغییر نسخه Runtime همراه برنامه، CI باید Project Routing، Agent/Provider/Session، Messageها، Permission/Question، Eventها و یک Write Tool واقعی را با Target جدید تأیید کند.
