نسخه Stable فعلی:

```text
v0.5.0
```

در زمان این Documentation Refresh، Branchهای `main` و `dev` روی همان Commit Validate‌شده مربوط به Release v0.5.0 قرار دارند.

بنابراین **فعلاً Feature Set مربوط به نسخه بعدی وجود ندارد که مستند شود.**

## Branch Discipline

- `main` فقط Stable Production است؛
- `dev` خط Integration برای Development Cycle بعدی است؛
- Feature/Fix Branch از `dev` شروع می‌شود؛
- Experimental Work تا Stable Promotion آگاهانه وارد `main` نمی‌شود.

## Development Build خصوصی

وقتی `dev` دوباره جلو برود، Build آزمایشی از **Preview Build** در GitHub Actions استفاده می‌کند و Stable npm `latest` را تغییر نمی‌دهد.

Workflow فعلی Review ZIP مربوط به Windows x64 می‌سازد و Artifact را 14 روز نگه می‌دارد.

## Rule مربوط به Documentation

Public Site اول Stable Behavior را مستند می‌کند.

بخش Development آینده فقط وقتی اضافه می‌شود که Behavior واقعی و Unreleased داخل Repository وجود داشته باشد. Version یا Capability آینده نباید از قبل ساخته شود.
