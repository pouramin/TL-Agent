در v0.5، Permission و Question هر دو Domainهای Native و First-class خود TL Studio هستند.

## Native Permission Engine

Permission Engine مرجع Authoritative برای Native Tool Execution است.

این بخش مالک موارد زیر است:

- Pending Request؛
- Allow once؛
- Reject؛
- Project-scoped Remembered Allow Rule؛
- Sensitive-action Restriction؛
- Policy Matching؛
- Enforcement؛
- Semantic Attention Event.

Browser فقط از Routeهای زیر استفاده می‌کند:

```text
/local/permissions*
```

## Read در برابر Write/Execute

Built-in Tool فقط‌خواندنی که Write/Execute/Network ندارد می‌تواند بدون Approval Prompt اجرا شود.

Write/Edit و Command Execution از Permission Authorization عبور می‌کنند.

برای Native Write/Edit، Matcher دقیق و امن در Scope Project می‌تواند Remember شود.

Request دارای Execute یا Network حساس است و به Reusable Approval تبدیل نمی‌شود.

Native Tool ناشناخته قابل Authorize نیست.

## Remembered Rule

Remembered Allow Ruleها داخل فایل Local زیر قرار دارند:

```text
permissions.json
```

TL Studio فقط Matcher دقیق قابل‌استفاده را نگه می‌دارد و Wildcard گسترده‌تر اختراع نمی‌کند.

Ruleها Project-scoped هستند و از Settings قابل مشاهده و Forget هستند.

## Native Question

Native Agent می‌تواند با این Tool Pause شود:

```text
interaction.question
```

Flow:

```text
Native Agent
→ Question Manager
→ /local/questions
→ Browser
→ Reply or Reject
→ Question Manager
→ Agent Resumes
```

Question به Session Scope می‌شود.

سیستم فعلی Multiple-choice، Multiple Selection، Custom Text، Default، Reject و Context Cancellation را پشتیبانی می‌کند.

تغییر Pending/Resolved مربوط به Question، Semantic Event از نوع `attention.changed` ایجاد می‌کند.

## مسئولیت User

Permission می‌تواند اجازه واقعی برای تغییر File یا اجرای Command بدهد. MCP Plugin Tool هم می‌تواند Capability درخواست کند.

قبل از Approval، Action و Context را بررسی کنید؛ مخصوصاً برای Command Execution یا Third-party Plugin Tool.
