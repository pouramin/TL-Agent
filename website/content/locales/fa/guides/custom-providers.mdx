تعریف Provider، Model Discovery، Model Catalog و Credentialهای Provider در اختیار خود TL Studio هستند.

## Protocolهای بومی مدل

| Protocol | Stable v0.6 |
| --- | --- |
| OpenAI-compatible Chat Completions | ✅ |
| OpenAI Responses | ✅ |
| Anthropic Messages | ✅ |
| Google Gemini generateContent | ✅ |

Model Request در حالت عادی مستقیماً از TL Studio به Endpoint تنظیم‌شدهٔ Provider می‌رود؛ فقط Bridgeهای رسمی حساب و Transport مربوط به Claude Web مسیر مستند و جداگانه دارند.

## راه‌اندازی Provider سفارشی

راه‌اندازی Provider سفارشی Discovery-first است. در حالت عادی این موارد کافی هستند:

- API Address؛
- API Type؛
- API Key.

بعد از آن TL Studio تلاش می‌کند Modelها را خودکار Discover کند. ورود دستی Model ID فقط Fallback صریح برای Model خصوصی یا فهرست‌نشده است.

## روش اتصال Providerها

| Provider | روش پیش‌فرض | رفتار Stable v0.6 |
| --- | --- | --- |
| **ChatGPT / Codex** | Account sign-in | Login رسمی Codex و Model Access مبتنی بر پلن از طریق Provider Bridge ایزوله |
| **GitHub Copilot** | Account slot رزروشده | Model Integration هنوز Deferred است |
| **Claude / Anthropic** | Account sign-in + API key | مسیر حساب Claude و مسیر دستی Anthropic API جدا می‌مانند |
| **Claude Web** | Chrome extension bridge | از Session احرازهویت‌شدهٔ Claude Web که متعلق به Chrome است استفاده می‌کند |
| **Google / Gemini** | API key | Preset مربوط به Gemini با پشتیبانی از Transport بومی Gemini |
| **Hugging Face** | API token | Preset مربوط به Inference Providers |
| **OpenRouter** | API key | Preset سازگار با OpenAI برای OpenRouter |

Helperهای مربوط به حساب ChatGPT و Claude فقط Authentication و Model Transport را فراهم می‌کنند. Session، Tool، Permission، تغییرات Project، Persistence و Agent Loop اصلی همچنان در اختیار TL Studio هستند.

### مرز Claude Web

برای Claude Web از Extension رسمی TL Studio Claude Web Bridge در Chrome Web Store استفاده می‌شود. اگر Extension نصب نباشد، TL Studio صفحهٔ نصب را باز می‌کند و بعد از نصب به‌صورت خودکار دوباره آن را Detect و Pair می‌کند.

Extension فقط نقش Inference Transport دارد. Session احرازهویت‌شده در اختیار Chrome می‌ماند و TL Studio Cookie یا Session Credential مربوط به Claude را کپی نمی‌کند. Readiness مربوط به این Bridge در Routing و Fallback هم لحاظ می‌شود.

## Credential Vault

Credential دستی API و Credential حساب در Slotهای جدا هستند.

اتصال حساب API Key دستی موجود را Overwrite نمی‌کند و Sign out هم آن را حذف نمی‌کند.

Secret وارد Browser Storage یا Provider JSON عادی نمی‌شود.

## دو مسیر JEV

JEV عمداً دو Integration جدا دارد:

- مسیر **JEV via OpenRouter** همان Provider/Model قدیمی را حفظ می‌کند؛
- مسیر **JEV Direct** یک Router Plugin سراسری است که مستقیم از TypeSafe System One و `jev-latest` استفاده می‌کند.

JEV Direct فقط Routing State را می‌گیرد و Model مناسب را برمی‌گرداند. Final Model Request، Tool، File، Permission، Session، Retry و Terminal همچنان متعلق به TL Studio هستند.
