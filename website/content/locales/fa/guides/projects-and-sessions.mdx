## Project Boundary

Project انتخاب‌شده مرز کاری TL Studio است.

File، Editor State، Search، Terminal Process، Preview، Session، Changes، Agent Context، Permission، Question و Plugin از نوع Project همگی Project فعال را دنبال می‌کنند.

هنگام Project Switch، Safety Ruleهای موجود حفظ می‌شوند: Unsaved Work محافظت می‌شود، Lifecycle مربوط به Terminal/Preview Cleanup می‌شود، Plugin Processها Restart یا Re-scope می‌شوند و Workspace State برای Project جدید Reload می‌شود.

## Native Session Domain

تمام Sessionهای فعال در v0.6 **Sessionهای خود TL Studio** هستند.

TL Studio مالک این بخش‌هاست:

- Session ID؛
- Create، Select، Rename و Delete؛
- Run و Abort؛
- Status؛
- Message و Activity؛
- Usage Metadata؛
- File Changes؛
- Persistence.

Browser از Routeهای Semantic زیر استفاده می‌کند:

```text
/local/sessions*
```

زیر Product دیگر Session Owner زنده و جداگانه‌ای وجود ندارد.

## Persistence محلی

TL Studio Semantic Session Snapshot را در Local State خودش نگه می‌دارد.

Snapshot می‌تواند شامل این موارد باشد:

- Session Metadata؛
- User/Assistant Transcript؛
- Agent/Model Selection؛
- Activity و Usage؛
- File Changes.

Persistence دارای Limit است و برای حفظ Product Transcript بین Restartها استفاده می‌شود.

قبل از Write شدن Snapshot، Payloadهای Inline با Prefix `data:` از Attachment حذف می‌شوند؛ Metadata Attachment می‌تواند کنار Message باقی بماند.

## Native Agent Lifecycle

Run عادی:

```text
Browser
→ TL Studio Session
→ Native Agent
→ Selected Provider
→ Optional Tool / Question / Permission
→ Final Assistant Response
→ Session Persistence + Semantic Events
```

Abort، Native Run فعال را Cancel می‌کند.

## Live Activity

Browser Updateهای Semantic را از این Route می‌گیرد:

```text
/local/events
```

Local Event Bus تنها Product Event Source برای Agent، Tool، Session، Question، Permission و Workspace Change است.

Persisted Session Data مرجع Transcript باقی می‌ماند و SSE برای Responsiveness استفاده می‌شود.
