TL Studio v0.5 یک **AI-native Development Workspace** است، نه Chat Application که یک Editor هم کنارش گذاشته شده باشد. Editor مرکز اصلی Layout باقی می‌ماند و Agent می‌تواند برای Collaboration بازتر شود یا وقتی Manual Coding مهم‌تر است Collapse شود.

## ساختار Workspace

Workspace دسکتاپ این بخش‌ها را دارد:

- **Global Top Bar** برای Product، Project فعال، Command Palette، Local Status، Preview، Appearance، Refresh و Account Surface؛
- **Activity Rail** برای Explorer، Search، Sessions، Changes و Settings؛
- **Context Sidebar** برای Activity انتخاب‌شده؛
- **Editor Workspace** برای File Tabها و Monaco؛
- **TL Agent Panel** در حالت Collapsed، Compact یا Focused؛
- **Terminal** به‌عنوان Bottom Panel قابل Resize؛
- **Live Preview** به‌عنوان Floating Local Window؛
- **Status Bar** برای Stateهای مطمئن و فشرده.

طراحی Desktop-first است. در Width کمتر ابتدا Density ثانویه کم می‌شود، بعد Context Sidebar و Agent Collapse می‌شوند تا فضای مفید Editor حفظ شود.

## Monaco Editor

Monaco به‌صورت Local Bundle و Lazy Load می‌شود. Editor سبک textarea هم Fallback باقی مانده است.

این بخش‌ها همچنان متعلق به TL Studio هستند، نه Monaco:

- Project Path و File Access؛
- Buffer/Model هر File؛
- Multi-tab State؛
- Save؛
- SHA-256 Revision Protection؛
- Save Conflict؛
- External-change Reconciliation؛
- Preview-only Media Tab.

برای Save از `Ctrl/Cmd+S` استفاده کنید.

## Explorer

Explorer عملیات واقعی Project را انجام می‌دهد:

- Open File؛
- Create File/Folder؛
- Rename و Delete؛
- Refresh Tree؛
- **Show in Folder** برای File فعال.

همه Filesystem Operationها داخل Boundary همان Project باقی می‌مانند.

## File Stateها

Tab باز می‌تواند این Stateها را داشته باشد:

- **Clean** وقتی Buffer با آخرین Disk Revision برابر است؛
- **Dirty** برای Edit ذخیره‌نشده؛
- **Agent modified** وقتی Session فعلی همان Path را تغییر داده و با Marker حرف `A` نشان داده می‌شود؛
- **Externally modified** وقتی SHA نسخه روی Disk تغییر کند؛
- **Deleted externally** که برای Buffer کثیف همچنان محافظت انجام می‌شود؛
- **Conflict** وقتی Save با Expected SHA قدیمی انجام شده باشد.

Marker مربوط به Agent فقط Session Change را نشان می‌دهد و سیستم Git Authorship نیست.

## Panelهای قابل Resize

سه Splitter اصلی داریم:

1. لبه راست Context Sidebar؛
2. لبه چپ TL Agent؛
3. لبه بالای Terminal.

Constraint فعلی شامل حداقل 180px برای Context Sidebar، حداقل 280px برای Agent بازشده، حدود 420px فضای هدف برای Editor و حداقل 96px برای Terminal بازشده است.

Geometry به‌صورت Local زیر این Key Persist می‌شود:

```text
tl-studio.workspace-layout.v1
```

## حالت‌های Agent

TL Agent Panel سه حالت Presentation دارد:

- **Collapsed** برای بیشترین فضای Editor؛
- **Compact** برای Collaboration عادی؛
- **Focused** برای Planning/Review با Agent بزرگ‌تر در کنار Editor.

این‌ها فقط Presentation را تغییر می‌دهند و هر سه از همان Native Session/Agent استفاده می‌کنند.

## Command Palette

Shortcut اصلی:

```text
Ctrl/Cmd + K
```

Commandهای فعلی فقط Behavior واقعی Product را ارائه می‌دهند؛ مثل Open Project، Explorer، Search، Switch Session، تغییر Agent State، Preview، Terminal، Change Model و Settings.

## Changes و Status Bar

بخش **Changes** بر Semantic Session Change تکیه دارد و می‌تواند File Path، Addition/Deletion و Patch را در صورت وجود نشان دهد. این بخش Full Git Client نیست.

Status Bar موارد قابل اتکا مثل Local Status، Change Count، Agent State، Model انتخاب‌شده، Cursor Position و Terminal Entry را نشان می‌دهد.

تا وقتی Data Source مطمئن برای Git Branch وجود نداشته باشد، Branch ساختگی در UI نمایش داده نمی‌شود.
