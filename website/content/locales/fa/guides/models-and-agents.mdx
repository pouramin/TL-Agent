در TL Studio فقط یک Runtime اصلی برای Agent وجود دارد: **TL Studio Native Agent**.

Model انتخاب‌شده باید از طریق Protocol Adapter پیاده‌سازی‌شده در خود TL Studio قابل اجرا باشد.

## Protocolهای بومی پایدار

نسخهٔ پایدار v0.6 این Protocolها را پشتیبانی می‌کند:

- OpenAI-compatible Chat Completions؛
- OpenAI Responses؛
- Anthropic Messages؛
- Google Gemini `generateContent`.

## Model Catalog و Credential

Provider Definition و Modelهای تنظیم‌شده داخل Local Provider Registry خود TL Studio هستند.

Provider UI می‌تواند Remote Model Catalog را Discover کند و Metadataهایی مثل Context/Output Limit، Tool Calling، Reasoning، Vision و Router Kind را Normalize کند.

Credential دستی API و Credential حساب جدا از هم باقی می‌مانند و وارد Agent Transcript نمی‌شوند.

## اجرای Native Agent

~~~text
Session Prompt
→ Native Agent
→ Selected Provider / Router-selected native model
→ Model Response
→ Tool Calls when requested
→ TL Studio Tool Executor
→ Tool Results back to Provider
→ Final Response
~~~

Model Turn مستقیم به‌صورت پیش‌فرض Timeout برابر 2 دقیقه دارد. Agent Routed برای کارهای سنگین‌تر Timeout برابر 4 دقیقه دارد.

## Model Router

نسخهٔ پایدار v0.6 این Routerهای سطح بالا را دارد:

- **Laya Router**؛
- **JEV Direct**.

هر دو از این Profileها استفاده می‌کنند:

- Balanced؛
- Lowest cost؛
- Best quality؛
- Fastest؛
- Free only.

Metadata هر Model می‌تواند شامل Enabled/Disabled، Cost Group، Quality از 1 تا 5 و Speed از 1 تا 5 باشد.

حالت **Free only** سخت‌گیرانه است؛ Model پولی قبل از Routing حذف می‌شود و حتی به‌عنوان Fallback استفاده نمی‌شود.

Failure، Cooldown، Retry و Fallback مربوط به Routing داخل Chat قابل مشاهده می‌مانند.

## مرز مالکیت

Router فقط Model بومی مناسب را انتخاب می‌کند.

Agent Loop، Context، فایل‌ها، Tool، Permission، Session، Retry، Fallback، Terminal، تغییرات Project و تمام ادامه‌های مدل → Tool → مدل همچنان در اختیار TL Studio هستند.
