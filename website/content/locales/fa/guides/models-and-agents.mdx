در TL Studio فقط یک مدل اصلی اجرا وجود دارد: **TL Studio Native Agent**.

Model انتخاب‌شده باید از طریق Protocol Adapter پیاده‌سازی‌شده در خود TL Studio قابل اجرا باشد.

## Protocolهای Native مدل

نسخهٔ پایدار v0.5 این Protocolها را پشتیبانی می‌کند:

- OpenAI-compatible Chat Completions؛
- OpenAI Responses؛
- Anthropic Messages.

در Development v0.6، Transport بومی Google Gemini generateContent هم اضافه شده است.

## Model Catalog

Provider Definition و Modelهای تنظیم‌شده داخل Local Provider Registry خود TL Studio هستند.

Provider UI می‌تواند Remote Model Catalog را Discover کند، Metadata مفید را Normalize کند و اجازه دهد فقط Modelهای موردنظر ذخیره شوند.

Metadata می‌تواند شامل این موارد باشد:

- Context Limit؛
- Output Limit؛
- Tool Calling؛
- Reasoning؛
- Vision؛
- Router Kind.

Capability ناشناخته در UI به‌صورت صریح باقی می‌ماند و بدون اطلاع کاربر فرض نمی‌شود.

## Credentialها

Credential دستی API و Credential حساب از هم جدا هستند.

در خط توسعهٔ 0.6، وقتی Account Adapter فعال و متصل باشد، Runtime ابتدا Credential حساب را Resolve می‌کند. API Key دستی جداگانه باقی می‌ماند و بعد از Sign out حساب همچنان قابل استفاده است.

Credential وارد Transcript مربوط به Agent نمی‌شود.

## اجرای Agent

برای Model پشتیبانی‌شده:

~~~text
Session Prompt
→ Native Agent
→ Selected Provider
→ Model Response
→ Tool Calls when requested
→ TL Studio Tool Executor
→ Tool Results back to Provider
→ Final Response
~~~

Agent از Cancellation و Guard برای Maximum Iteration، Tool Round، تعداد Tool در هر Round و تکرار Tool Call یکسان استفاده می‌کند.

## تعامل بومی

Agent می‌تواند Tool داخلی interaction.question را Call کند تا Pause شود و Structured Input از User بگیرد.

Question می‌تواند Choice، Multiple Selection، Custom Text و Default داشته باشد.

## منبع Toolها

Agent، Tool Definition را از این منابع می‌گیرد:

1. Toolهای داخلی و بومی TL Studio؛
2. MCP Pluginهای فعال و سازگار برای Project.

هر دو وارد همان Tool Model و Permission System می‌شوند.

## مسیرهای حسابی در Development

در خط توسعهٔ 0.6، Model می‌تواند از حساب متصل OpenRouter، Hugging Face، Google/Gemini یا ChatGPT/Codex Resolve شود.

OpenRouter، Hugging Face و Gemini، Credential را از Account Adapter خود TL Studio می‌گیرند. برای ChatGPT، Client رسمی OpenAI Codex، OAuth و Model Access مبتنی بر پلن ChatGPT را داخل CODEX_HOME ایزولهٔ مخصوص TL Studio مدیریت می‌کند.

در Model Turnهای ChatGPT، Codex CLI رسمی فقط نقش Provider Bridge را دارد. Session، چرخهٔ بیرونی مدل/Tool/مدل، Tool Execution، Permission، تغییرات پروژه و Persistence همچنان در اختیار TL Studio هستند.
