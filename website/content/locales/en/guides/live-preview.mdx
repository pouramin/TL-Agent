TL Studio uses a capability-driven Preview system rather than treating Preview as only a root `index.html`.

## Previewable file types

The current capability registry recognizes:

- HTML;
- SVG and raster images;
- PDF;
- video;
- audio;
- rendered Markdown;
- rendered plain text/log files.

Supported examples include PNG/JPEG/WebP/GIF/AVIF/BMP/APNG, MP4/WebM, MP3/WAV/OGG/M4A/AAC/FLAC, and standard PDF/Markdown/Text files.

Previewable binary/media files can open as real read-only Workspace tabs.

## Active-file Preview

The floating Preview can follow the active previewable file in the Editor workspace.

If no explicit file is selected, TL Studio can choose a root `index.html`, another available previewable file, or a supported Node dev-server workflow.

## Node development server

If `package.json` contains a `dev` script, TL Studio can run:

```text
npm run dev
```

through its native process manager and detect a loopback URL reported by the server.

Only local Preview URLs are accepted.

## PDF

PDF is served inline with the correct MIME/disposition and HTTP range support so the Browser's native PDF viewer can seek through the file.

## Floating window

Live Preview is draggable and resizable from all four edges and all four corners.

Geometry is stored locally under:

```text
tl-studio.preview-window
```

Saved geometry is clamped back into a usable viewport region when necessary.

## Security boundary

Previewed Project code does **not** share TL Studio's privileged control origin.

Static/file Preview runs on a separate loopback origin and Node Preview accepts loopback URLs only.

The Preview file server is read-only and Project path traversal/symlink escape protection remains in force.
