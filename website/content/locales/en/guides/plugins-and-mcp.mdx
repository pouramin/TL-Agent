Stable v0.6 includes a **TL Studio-owned Plugin/MCP system**. Enabled MCP servers can contribute tools to the same Tool Registry and Native Agent used by built-in coding tools.

## Current MCP support

```text
Type:      MCP
Transport: stdio
Scope:     project or global
```

Custom project-scoped MCP servers remain supported.

Saving a Plugin does not start its command. Enabling is a separate explicit action and TL Studio asks for confirmation before starting configured local MCP commands.

## Plugin UI

Plugins are shown as provider-style cards across:

- Available integrations;
- Included with TL Studio;
- Added by you.

The grid is responsive: 3 columns on wide desktop, 2 on medium layouts, and 1 on narrow layouts.

## Graphify

Graphify is installed once globally, while generated graph data remains project-local.

A Project without graph data shows **Graph Missing**. Graph creation is explicit through **Build Graph**; adding Graphify does not build automatically.

The reliable local build uses:

~~~bash
graphify extract . --code-only
graphify export html
~~~

Outputs:

~~~text
graphify-out/graph.json
graphify-out/graph.html
~~~

Global MCP processes restart with the active Project working directory when Projects change.

## Router plugins

Router plugins are separate from MCP Tool plugins. They influence model selection but never enter the Tool Registry.

### Laya Router

Laya is installed as a global Plugin/MCP integration and can also appear as a top-level Model Router.

### JEV Direct

JEV Direct is a separate global router that calls TypeSafe System One directly with `jev-latest`.

Both routers hand the selected native model back to TL Studio. They do not own tools, permissions, files, Sessions, Terminal, retries, or the Agent loop.

## Secrets and permissions

Plugin environment secrets are stored through the TL Studio credential vault.

MCP Tools discovered from enabled servers still pass through TL Studio's Permission authorizer before execution.
