Stable v0.5 includes a **TL Studio-owned Plugin/MCP system**. Enabled MCP servers can contribute tools to the same Tool Registry and Native Agent used by built-in coding tools.

## Current support

The current Plugin system supports:

```text
Type:      MCP
Transport: stdio
Scope:     project or global
```

HTTP/SSE MCP transports are not part of the current implementation.

## Add a Plugin

Open **Settings → Plugins → Add plugin** and configure:

- name and optional description;
- local MCP command;
- one argument per line;
- Project or Global scope;
- optional working directory;
- required environment variable names and secret values.

Saving a Plugin **does not start its command**. New Plugins are saved disabled.

Enabling is a separate explicit action and TL Studio asks for confirmation before it starts the configured local MCP command.

## Project and Global scope

A Project-scoped Plugin applies only to its saved Project.

A Global Plugin is available across Projects, but the running MCP process is restarted when the active Project changes so it does not keep operating with the previous Project as its working directory.

Project identity is normalized so equivalent paths, junctions, and symlink-resolved directory spellings do not accidentally create cross-Project leakage.

## Secrets

Environment secret values are stored through the TL Studio credential vault.

`plugins.json` stores the Plugin definition and environment variable names/configuration state, not the secret values themselves.

## Test Connection

**Test Connection** starts the MCP process temporarily, performs MCP initialization, discovers Tools, attempts Resource discovery, and then closes the temporary client.

The current MCP client uses protocol version:

```text
2024-11-05
```

`tools/list` is required. `resources/list` is optional so a tools-only MCP server can still connect.

## Agent tools

Tools discovered from an enabled MCP server are added dynamically to TL Studio's Tool Registry and the Native Agent's tool definitions.

They still pass through TL Studio's Permission authorizer before execution. TL Studio uses MCP annotations when available and conservative name/capability heuristics otherwise.

If an MCP process or transport fails during a Tool call, TL Studio can restart the client once and retry that call.

## Bundled Plugin foundation

TL Studio supports version-pinned Plugins staged inside a Release package. Bundled Plugins cannot be removed, but can be enabled or disabled.

**The v0.5.0 bundled-plugin catalog is empty.** No third-party MCP Plugin ships by default in this stable build.
