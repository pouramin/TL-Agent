TL Studio owns Provider definitions, model discovery, the model catalog shown in the product, and Provider credentials.

## Native model protocols

| Protocol | Stable v0.6 |
| --- | --- |
| OpenAI-compatible Chat Completions | ✅ |
| OpenAI Responses | ✅ |
| Anthropic Messages | ✅ |
| Google Gemini generateContent | ✅ |

Model requests go directly from TL Studio to the configured Provider endpoint, except for documented provider-owned account bridges and Claude Web transport.

## Custom Provider setup

Custom Provider setup is discovery-first. Normally you provide:

- API address;
- API type;
- API key.

TL Studio then attempts model discovery automatically. Manual Model ID entry remains an explicit fallback for private or unlisted Models.

## Provider connections

| Provider | Default setup | Stable v0.6 behavior |
| --- | --- | --- |
| **ChatGPT / Codex** | Account sign-in | Official Codex login and plan-backed model access through an isolated provider bridge |
| **GitHub Copilot** | Reserved account slot | Model integration remains deferred |
| **Claude / Anthropic** | Account sign-in + API key | Claude account path and manual Anthropic API path stay separate |
| **Claude Web** | Chrome extension bridge | Uses the authenticated Claude Web session already owned by Chrome |
| **Google / Gemini** | API key | Gemini preset with native Gemini transport support |
| **Hugging Face** | API token | Inference Providers preset |
| **OpenRouter** | API key | OpenAI-compatible OpenRouter preset |

ChatGPT and Claude account helpers provide authentication/model transport only. TL Studio remains authoritative for Sessions, tools, permissions, project mutations, persistence, and the outer Agent loop.

### Claude Web boundary

Claude Web uses the TL Studio Claude Web Bridge extension from the Chrome Web Store. If the extension is missing, TL Studio opens its installation page and automatically rechecks/pairs after installation.

The extension is inference-only. Chrome keeps the authenticated Claude session; TL Studio does not copy Claude cookies or session credentials. Readiness is included in routing/fallback eligibility.

## Credential vault

Manual API credentials and account credentials use separate vault slots.

Connecting an account does not overwrite an existing manual API key, and signing out does not delete it.

Secrets do not appear in Browser storage or normal Provider JSON state.

## JEV paths

JEV intentionally has two separate paths:

- **JEV via OpenRouter** remains the legacy provider/model integration;
- **JEV Direct** is a global Router plugin using TypeSafe System One with `jev-latest`.

JEV Direct receives routing state and returns a model decision. It does not proxy the final model request or own TL Studio tools, files, permissions, sessions, retry logic, or Terminal.
