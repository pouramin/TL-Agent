TL Studio v0.5 owns Provider definitions, model discovery, the Model catalog presented to the product, and Provider credentials.

## Native protocol adapters

TL Studio implements its supported model protocol adapters inside the product. Configure a connection with the protocol family exposed by the stable build, a Base URL, credential, and one or more Models.

## Discover Models

Use **Test / Discover Models** before saving when the Provider exposes a model-list API.

TL Studio validates the Base URL, sends the discovery request, normalizes the returned Models, and presents a searchable catalog.

The discovery layer can normalize:

- Model ID and name;
- context/output limits;
- Tool Calling;
- Reasoning;
- Vision;
- Router kind.

You can select visible Models, clear selection, search the catalog, or keep manual Model entry for a private/unlisted Model.

## Discovery safety

Provider discovery:

- accepts valid HTTP(S) Base URLs without embedded credentials;
- uses a 15-second request timeout;
- limits catalog responses to 8 MiB;
- caps normalized catalogs at 5000 Models;
- blocks cross-origin redirects;
- allows at most a small bounded redirect chain.

For compatible paginated discovery endpoints, TL Studio uses a bounded page count.

## Cached catalog fallback

A successful catalog can be cached locally in:

```text
model-catalog-cache.json
```

If later live discovery fails for a non-authentication reason, TL Studio can return the matching cached catalog as stale data.

Authentication/authorization failures do **not** silently fall back to cache.

## Authenticated discovery

When a configured model endpoint requires authentication for catalog discovery, TL Studio uses the saved credential and treats authentication failures as explicit failures rather than silently falling back.

## Provider registry

Saved definitions live in TL Studio's versioned:

```text
providers.json
```

The registry stores Provider ID/name, protocol, Base URL, Model definitions, capability flags, and optional limits.

It does not contain API keys.

## Credential vault

API keys live in the TL Studio credential vault:

- Windows DPAPI;
- macOS Keychain when available;
- Linux Secret Service through `secret-tool` when available;
- encrypted private-file fallback otherwise.

Provider calls use this TL Studio-owned credential directly.

## Account-based Provider foundation

TL Studio also has a generic `/local/provider-accounts*` adapter domain for future official account-backed integrations.

**The current v0.5.0 build registers no account adapters.** The Providers UI therefore reports that no account-based Provider integrations are available in this build. Do not expect an account sign-in flow unless a future build explicitly adds a documented adapter.
