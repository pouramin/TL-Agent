In v0.5, native execution is not an optional path — it is the core TL Studio Agent architecture.

## Execution flow

```text
Browser
→ /local/sessions/{id}/runs
→ TL Studio Session domain
→ Native Agent
→ selected Provider
→ normalized model response
→ TL Studio Tool Executor
→ native subsystem or MCP Plugin
→ structured Tool result
→ Provider continuation
→ final response
→ persistence + /local/events
```

Unsupported Provider protocols or capabilities return explicit errors rather than being routed to another local engine.

## Built-in executable Tools

The current Native Agent exposes these built-in executable Tool IDs:

```text
files.read
files.list
files.write
files.edit
search.content
terminal.command
interaction.question
```

The file/search/terminal Tools reuse TL Studio's existing Project boundary, symlink protection, Search, process, cancellation, and Permission infrastructure.

## Interactive Question Tool

`interaction.question` can submit between 1 and 20 question blocks.

A question can contain a header, question text, selectable options, multiple-selection behavior, custom text, and a default custom answer.

The Agent pauses until the Question Manager receives a reply, rejection, or cancellation.

## Dynamic MCP Tools

Enabled MCP Plugins can contribute additional Tool definitions for the active Project.

They are dynamically added to the Agent's Tool list and TL Studio Tool Registry. Plugin Tool calls are resolved by the Plugin Manager and still go through TL Studio's native Permission authorizer.

## Tool Registry

The Tool Registry provides product-facing descriptors including Tool ID, name, description, category, Permission class, capabilities, input schema, presentation hint, source, and Plugin ID where relevant.

The registry describes tools; actual authorization and execution remain separate steps.

## Safety and loop guards

The Native Agent has explicit guards for:

- maximum Agent iterations;
- maximum Tool rounds;
- maximum Tools in one round;
- repeated identical Tool calls;
- context cancellation.

Tool inputs are treated as untrusted. Unknown built-in Tool IDs are rejected.

Command execution has bounded timeouts and uses the TL Studio process manager.
