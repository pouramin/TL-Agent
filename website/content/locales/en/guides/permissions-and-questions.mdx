Permissions and Questions are first-class TL Studio native domains in v0.6.

## Native Permission Engine

The Permission Engine is authoritative for native Tool execution.

It owns:

- pending requests;
- allow-once decisions;
- rejection;
- Project-scoped remembered allow rules;
- sensitive-action restrictions;
- policy matching;
- enforcement;
- semantic attention events.

The Browser uses only:

```text
/local/permissions*
```

## Read versus write/execute

Read-only built-in Tools without write/execute/network capability can run without an approval prompt.

Write/edit and command execution go through Permission authorization.

For native write/edit Tools, a safe exact Project-scoped matcher can be remembered.

Execute- or network-capable requests are sensitive and cannot be remembered as reusable approvals.

Unknown native Tools cannot be authorized.

## Remembered rules

Remembered allow rules live locally in:

```text
permissions.json
```

TL Studio uses exact reusable matchers rather than inventing broader wildcard rules.

Rules are Project-scoped and can be inspected/forgotten from Settings.

## Native Questions

The Native Agent can pause through:

```text
interaction.question
```

The flow is:

```text
Native Agent
→ Question Manager
→ /local/questions
→ Browser
→ reply or reject
→ Question Manager
→ Agent resumes
```

Questions are scoped to the Session.

The current system supports multiple-choice options, multiple selection, custom text answers, defaults, rejection, and context cancellation.

Pending/resolved Question changes emit semantic `attention.changed` events.

## Human responsibility

Permissions can authorize real local file changes and commands. MCP Plugin tools can also request capabilities.

Read the requested action and context before approval, especially for command execution or third-party Plugin tools.
