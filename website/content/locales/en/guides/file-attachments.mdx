title: File attachments
description: Attach images, PDFs, and text/code files to native TL Studio Agent prompts.

The Agent composer accepts local files as structured prompt parts.

## Ways to attach

- click the **+** attachment button;
- select multiple files;
- drag/drop files onto the composer;
- paste files from the clipboard.

Attachments appear as chips and can be removed before send.

## Supported UI formats

The current composer accepts:

- PNG, JPEG, WebP, and GIF images;
- PDF;
- text and common code/config formats.

SVG is normalized as text input rather than image input.

## Limits

Current client-side limits are:

- **8 files** per Prompt;
- **10 MiB per file**;
- **20 MiB total** pending attachments.

Unsupported binary formats are rejected before send.

## Native Session behavior

Attachments are sent through TL Studio's native Session run contract.

Sent attachment metadata can remain associated with the user Message in semantic Session history. Inline `data:` payloads are stripped before persisted Session snapshots are written.

Pending attachments are cleared after a successful send, when starting a new Session, or on Project switch. If send fails before acceptance, pending files can remain for retry.

## Provider capability

Composer acceptance does not guarantee that every selected Provider/Model can consume every binary format.

Model-side multimodal behavior depends on the native Provider protocol and selected Model.

## Privacy

TL Studio does not upload attachments to a TL Studio-owned cloud backend.

Content used for a model request can be sent directly to the Provider endpoint selected by the user.
