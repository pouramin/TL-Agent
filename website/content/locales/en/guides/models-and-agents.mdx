Stable v0.5 uses one core execution mode: the **TL Studio Native Agent**.

There is no local fallback coding engine. A Provider/Model must be executable through TL Studio's supported native Provider protocols and capabilities.

## Provider protocols

Current direct model protocols are:

- OpenAI-compatible Chat Completions;
- OpenAI Responses;
- Anthropic Messages.

The selected Provider endpoint receives model requests directly from TL Studio.

## Model catalog

Provider definitions and configured Models live in TL Studio's local Provider registry.

The Provider UI can also discover a remote model catalog, normalize useful metadata, and let you choose which Models to save.

Metadata can include:

- context limit;
- output limit;
- Tool Calling capability;
- Reasoning capability;
- Vision capability;
- Router kind.

When a Provider does not publish Tool capability metadata, the UI lets you decide whether unknown capability should be treated as supporting Tool Calling when saving the Model.

## Agent execution

For a selected supported Model:

```text
Session prompt
→ Native Agent
→ Provider model response
→ Tool calls when requested
→ TL Studio Tool Executor
→ Tool results back to Provider
→ final response
```

The Agent includes cancellation plus guards for maximum iterations, Tool rounds, Tools per round, and repeated identical Tool calls.

## Native interaction

The Agent can call the built-in `interaction.question` Tool to pause and ask the user for structured input.

Questions can include choices, multiple selection, custom text, and defaults.

## Tool sources

The Agent can receive Tool definitions from two sources:

1. built-in native TL Studio Tools;
2. enabled compatible MCP Plugins for the active Project.

Both enter the same Agent-facing Tool model and Permission system.
