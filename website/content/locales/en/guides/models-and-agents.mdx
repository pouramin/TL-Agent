TL Studio uses one core execution model: the **TL Studio Native Agent**.

A selected Model must be executable through a protocol adapter implemented by TL Studio.

## Stable native model protocols

Stable v0.6 supports:

- OpenAI-compatible Chat Completions;
- OpenAI Responses;
- Anthropic Messages;
- Google Gemini `generateContent`.

## Model catalog and credentials

Provider definitions and configured Models live in TL Studio's local Provider Registry.

The Provider UI can discover remote model catalogs and normalize metadata such as context/output limits, Tool Calling, Reasoning, Vision, and Router kind.

Manual API credentials and account-backed credentials remain separate and never enter the Agent transcript.

## Native Agent execution

~~~text
Session prompt
→ Native Agent
→ selected Provider / router-selected native model
→ Model response
→ Tool calls when requested
→ TL Studio Tool Executor
→ Tool results back to Provider
→ final response
~~~

Direct/default model turns use a 2-minute timeout. Routed Agent model turns use a 4-minute timeout for heavier routed work.

## Model routers

Stable v0.6 includes top-level routing through:

- **Laya Router**;
- **JEV Direct**.

Both support these profiles:

- Balanced;
- Lowest cost;
- Best quality;
- Fastest;
- Free only.

Per-model routing metadata can include enabled/disabled state, cost group, quality 1–5, and speed 1–5.

**Free only is strict:** paid models are removed from the candidate set and are never used as fallback.

Router failures, cooldowns, retries, and fallback activity remain visible in Chat.

## Ownership boundary

A router chooses a native model only.

TL Studio still owns the Agent loop, context, filesystem, tools, permissions, sessions, retries, fallback, Terminal, project mutations, and every model → Tool → model continuation.
