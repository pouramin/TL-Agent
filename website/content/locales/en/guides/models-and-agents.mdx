TL Studio uses one core execution model: the **TL Studio Native Agent**.

A selected Model must be executable through a protocol adapter implemented by TL Studio.

## Native model protocols

Stable v0.5 supports:

- OpenAI-compatible Chat Completions;
- OpenAI Responses;
- Anthropic Messages.

Development v0.6 additionally includes native Google Gemini generateContent transport.

## Model catalog

Provider definitions and configured Models live in TL Studio's local Provider Registry.

The Provider UI can discover a remote model catalog, normalize useful metadata, and let you choose which Models to save.

Metadata can include:

- context limit;
- output limit;
- Tool Calling;
- Reasoning;
- Vision;
- Router kind.

Unknown capability metadata remains explicit in the UI rather than being silently assumed.

## Credentials

Manual API credentials and account-backed credentials are separate.

In the 0.6 development line, the runtime resolves a connected account credential first when an account adapter is active. A manual API key remains stored separately and can still be used after account sign-out.

Credential material never enters the Agent transcript.

## Agent execution

For a selected supported Model:

~~~text
Session prompt
→ Native Agent
→ selected Provider
→ Model response
→ Tool calls when requested
→ TL Studio Tool Executor
→ Tool results back to Provider
→ final response
~~~

The Agent includes cancellation plus guards for maximum iterations, Tool rounds, Tools per round, and repeated identical Tool calls.

## Native interaction

The Agent can call the built-in interaction.question Tool to pause and ask the user for structured input.

Questions can include choices, multiple selection, custom text, and defaults.

## Tool sources

The Agent can receive Tool definitions from:

1. built-in native TL Studio Tools;
2. enabled compatible MCP Plugins for the active Project.

Both enter the same Agent-facing Tool model and Permission system.

## Development account paths

The 0.6 development line can resolve Models through connected OpenRouter, Hugging Face, Google/Gemini, and ChatGPT/Codex accounts.

OpenRouter, Hugging Face, and Gemini resolve credentials inside TL Studio's account adapters. ChatGPT uses OpenAI's official Codex client for ChatGPT OAuth and plan-backed model access under an isolated TL Studio-specific CODEX_HOME.

For ChatGPT model turns, the official Codex CLI acts only as a provider bridge. TL Studio still owns Session lifecycle, the outer model/tool/model loop, Tool execution, Permission handling, project mutations, and persistence.
