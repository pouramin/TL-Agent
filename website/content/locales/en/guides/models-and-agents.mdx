TL Agent presents the agents, providers, and models exposed through its bundled runtime. It does not create a separate model router or model-inference backend of its own.

## Agents

The primary coding workflow uses the product-facing `code` agent. Agent selection belongs to the TL Agent workspace; execution is handled underneath by the bundled runtime.

## Models and providers

Models can come from the hosted account flow available in TL Agent or from a compatible custom endpoint you add in **Settings → Providers**. TL Agent sends the selected provider/model reference to the local runtime when starting work.

See [Custom providers](./custom-providers) for the supported API families and storage/security model.

## Hosted account login

For hosted models, TL Agent surfaces the device authorization flow provided by the local runtime. Credentials and model inference are not routed through TL Agent-owned cloud infrastructure.

## Provider failures

Transient provider failures can happen even when TL Agent and the local runtime are healthy. When the runtime finishes its retry cycle with a retryable provider error, TL Agent can offer a **Resume** action that continues from the preserved workspace state instead of starting over.
