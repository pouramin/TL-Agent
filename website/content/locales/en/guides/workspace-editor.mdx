TL Studio v0.5 is an **AI-native development workspace**, not a chat window with an Editor attached. The Editor remains the visual center of gravity while the Agent can expand for collaboration or collapse when manual coding is primary.

## Workspace layout

The persistent desktop workspace is composed of:

- **Global Top Bar** — product identity, current Project, Command Palette entry, Local status, Preview, appearance, refresh, and account surface;
- **Activity Rail** — Explorer, Search, Sessions, Changes, and Settings;
- **Context Sidebar** — the content for the selected Activity;
- **Editor Workspace** — file tabs and Monaco;
- **Agent panel** — Collapsed, Compact, or Focused;
- **Terminal** — resizable bottom panel;
- **Live Preview** — floating local tool window;
- **Status Bar** — compact reliable state.

The product is desktop-first and adapts by reducing secondary density, collapsing the Context Sidebar, then collapsing the Agent before sacrificing useful Editor width.

## Monaco Editor

Monaco Editor is bundled locally and loaded lazily. A lightweight textarea Editor remains as fallback.

TL Studio, not Monaco, owns:

- Project paths and file access;
- one buffer/model per open file;
- multi-tab state;
- save operations;
- SHA-256 revision protection;
- save-conflict handling;
- external-change reconciliation;
- Preview-only media tabs.

Use `Ctrl/Cmd+S` to save the active file.

## Explorer

The Explorer supports real Project operations:

- open files;
- create files and folders;
- rename and delete;
- refresh the tree;
- reveal the active file with **Show in Folder**.

Filesystem operations remain confined to the selected Project.

## File states

Open tabs can represent several real states:

- **Clean** — buffer matches the last known disk revision;
- **Dirty** — unsaved local edits;
- **Agent modified** — the current semantic Agent Session reports that path as changed, shown with an explicit `A` marker;
- **Externally modified** — disk SHA changed while the file was open;
- **Deleted externally** — clean tabs may close while dirty buffers remain protected;
- **Conflict** — a save used a stale expected SHA and needs an explicit decision.

The Agent marker is Session-change information, not Git authorship.

## Resizable panels

The current workspace has three drag splitters:

1. Context Sidebar right edge;
2. Agent panel left edge;
3. Terminal top edge.

Current constraints include a 180px minimum Context Sidebar, 280px minimum expanded Agent, about 420px useful Editor target, and 96px minimum expanded Terminal.

Panel geometry is stored locally under:

```text
tl-studio.workspace-layout.v1
```

## Agent presentation states

The Agent panel has:

- **Collapsed** — narrow rail, maximum Editor space;
- **Compact** — normal coding collaboration;
- **Focused** — wider Agent surface for planning/review while keeping the Editor present.

This changes presentation only; all states use the same native Session and Agent implementation.

## Command Palette

Open the Command Palette with:

```text
Ctrl/Cmd + K
```

Current commands expose implemented behavior such as opening a Project, Explorer, Project Search, switching Session, changing Agent presentation state, opening Preview, toggling Terminal, changing Model, and opening Settings.

## Changes and Status Bar

The **Changes** view is Session-change oriented. It can show changed file paths, additions/deletions, and patch data where available; it is not a complete Git client.

The Status Bar shows reliable product state such as Local service state, change count, Agent state, selected Model, cursor position, and Terminal entry.

TL Studio intentionally does not display a Git branch until it has a reliable branch data source.
