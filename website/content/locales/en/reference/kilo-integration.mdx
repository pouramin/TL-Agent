Kilo Code is the current upstream agent runtime bundled underneath TL Agent. This page exists for maintainers and compatibility debugging; it is not the product identity or normal user workflow.

## Pinned compatibility

TL Agent pins a known Kilo version in `KILO_VERSION` and validates the product-facing HTTP API used by Kilo's official coding client for that version.

For the current compatibility target, the primary coding path uses product routes for agents, providers, sessions, status, messages, asynchronous prompts, global events, permissions, questions, and device authorization.

## Adapter boundary

Browser-side runtime calls are centralized in:

```text
cmd/launcher/web/kilo-api.js
```

UI modules should not build runtime endpoint paths directly. Keeping compatibility logic in one adapter makes upstream upgrades reviewable and testable.

## Upgrade rule

Before changing `KILO_VERSION`, TL Agent CI must verify project routing, agent/provider/session shapes, messages, permissions/questions, events, and a real write-tool flow against the new runtime.
