TL Agent is built around a local product layer and a bundled agent runtime.

```text
Browser workspace
  ↓ localhost
TL Agent UI + Go launcher
  ├─ project picker
  ├─ sessions / files / changes
  ├─ provider settings UI
  ├─ retryable provider recovery UI
  ├─ local state + appearance preferences
  ├─ security boundary
  └─ authenticated reverse proxy
       ↓
Bundled agent runtime
       ├─ sessions / agents / tools
       ├─ provider config + local credential store
       ├─ provider integrations / model execution
       └─ project execution
```

## TL Agent owns

- the standalone browser workspace;
- local launch and process lifecycle;
- project selection;
- the reverse-proxy/security boundary;
- packaging, releases, and the TL Agent brand;
- user-facing session, file, changes, permission, provider-settings, recovery, and appearance UX.

## Runtime owns

The bundled runtime handles agent execution, tools, session internals, filesystem/tool calls, provider configuration persistence, provider credentials, and model execution.

The distinction is architectural rather than product-facing: users operate **TL Agent** while runtime-specific implementation details stay behind the adapter boundary.
