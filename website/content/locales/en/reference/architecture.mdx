TL Agent is built around a local product layer and an upstream agent runtime.

```text
Browser workspace
  ↓ localhost
TL Agent UI + Go launcher
  ├─ project picker
  ├─ sessions / files / changes
  ├─ provider settings UI
  ├─ retryable provider recovery UI
  ├─ local state + appearance preferences
  ├─ security boundary
  └─ authenticated reverse proxy
       ↓
Bundled Kilo runtime
       ├─ sessions / agents / tools
       ├─ provider config + local auth store
       ├─ provider integrations / model execution
       └─ project execution
```

## TL Agent owns

- the standalone browser workspace;
- local launch and process lifecycle;
- project selection;
- the reverse-proxy/security boundary;
- packaging, releases, and the TL Agent brand;
- user-facing session, file, changes, permission, provider-settings, recovery, and appearance UX.

## Runtime owns

Kilo remains responsible for agent execution, tools, session internals, filesystem/tool calls, provider configuration persistence, provider credentials in its local auth store, and model execution.

The distinction is architectural and product-facing: users operate TL Agent while Kilo remains an upstream runtime component under the hood.
