The Browser talks directly to TL Studio's local product API.

## Core route families

The Browser-facing product domains include:

```text
/local/status
/local/health
/local/path
/local/agents
/local/project
/local/pick-directory

/local/providers/*
/local/provider-accounts*
/local/sessions*
/local/questions*
/local/permissions*
/local/events

/local/plugins*
/local/tools

/local/search
/local/process*
/local/preview*
```

Feature modules should call these TL Studio contracts through the typed Browser API layer rather than constructing ad-hoc backend behavior.

## Sessions

`/local/sessions*` owns native Session reads and mutations, including create, update, delete, run, abort, Messages, status, usage, and Changes.

## Questions and Permissions

`/local/questions*` exposes native interactive Question state.

`/local/permissions*` exposes pending Permission requests and remembered Project-scoped rules.

Both Browser domains use TL Studio-owned semantic request/response shapes.

## Events

`/local/events` is the semantic SSE stream for Browser responsiveness.

The source is TL Studio's local Event Bus.

## Providers

`/local/providers/config` is the native Provider registry surface.

`/local/providers/discover` performs bounded remote Model discovery.

`/local/provider-accounts*` is an adapter domain for future official account-backed Provider integrations. v0.5.0 currently has no registered account adapter.

## Tools and Plugins

`/local/tools` returns the current TL Studio Tool Registry, including dynamic MCP Tool descriptors when enabled Plugins are available for the Project.

`/local/plugins*` manages saved Plugin definitions, explicit enablement, testing, Project attachment, and product-aware integration actions.

## Maintainer rule

New Browser product behavior should be modeled as a TL Studio-owned local domain and exposed through the typed Browser API layer.
