```text
v0.5.0
```

Current development version:

```text
0.6.0-alpha.1
```

`dev` is currently **5 commits ahead of `main`**. Those commits update version/readiness metadata only; the implemented user-facing product behavior is still the same validated feature set shipped in v0.5.0.

## Branch discipline

- `main` is stable production;
- `dev` is the integration line for the next development cycle;
- feature/fix branches start from `dev`;
- experimental work does not enter `main` until deliberate stable promotion.

## Private development builds

Development builds use GitHub Actions **Preview Build** artifacts rather than the stable npm `latest` channel.

The current Preview workflow produces a Windows x64 review ZIP and retains it for 14 days.

## Documentation rule

The public site documents stable behavior first.

Development documentation must distinguish implemented unreleased behavior from version/readiness bookkeeping. Planned capabilities are not documented as shipped features.
