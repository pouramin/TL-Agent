## Source layout

The Go launcher and local product domains live under:

~~~text
cmd/launcher/
~~~

Browser source is strict TypeScript under:

~~~text
cmd/launcher/ui/
~~~

Generated Browser JavaScript is emitted under:

~~~text
cmd/launcher/web/
~~~

Public Fumadocs documentation lives under:

~~~text
website/
~~~

## Local checks

Before proposing product changes:

~~~bash
npm install --ignore-scripts --no-audit --no-fund
npm run check:web
npm run build:web
go test ./...
go vet ./...
~~~

Run the relevant contract/regression scripts when changing model connections, Sessions, Questions, Permissions, Tools, Plugins/MCP, Browser behavior, Provider Accounts, or release behavior.

## Architecture rules

- New Browser behavior should use TL Studio-owned /local/* product domains.
- Model connection definitions, discovery, credentials, account adapters, and direct model execution belong to TL Studio.
- Sessions, Questions, Permissions, and semantic Events belong to TL Studio.
- Built-in Tool execution should reuse Project filesystem/Search/process/Permission infrastructure.
- Plugin/MCP Tools must continue through the TL Studio Tool Registry and Permission path.
- Secrets must stay out of ordinary JSON configuration and Browser storage.
- Monaco is an Editor engine, not a filesystem authority.
- Previewed Project code stays on a separate loopback origin.
- Do not load Editor assets from a CDN.

## Provider Account rules

Provider Account integrations must use documented public third-party mechanisms.

OAuth and API credential material stays on the Go side and in the credential vault.

Manual API credentials and account credentials remain separate.

An account integration must not replace TL Studio's Native Agent or Tool execution model.

## Release and documentation rules

Stable behavior on main may be documented as released behavior.

Development behavior from dev may be documented only when it is clearly labeled as a development preview.

Do not present an unreleased capability as part of the stable npm/GitHub Release path.

Historical implementation wording does not belong in current product documentation.
