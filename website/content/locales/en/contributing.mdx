## Source layout

The Go launcher and native local product domains live under:

```text
cmd/launcher/
```

Browser source is strict TypeScript under:

```text
cmd/launcher/ui/
```

Generated Browser JavaScript is emitted under:

```text
cmd/launcher/web/
```

Do not edit generated JavaScript as the primary source.

Public Fumadocs documentation lives under:

```text
website/
```

## Local checks

Before proposing product changes:

```bash
npm install --ignore-scripts --no-audit --no-fund
npm run check:web
npm run build:web
go test ./...
go vet ./...
```

Run the relevant contract/regression scripts when changing model connections, Session, Question, Permission, Tool, Plugin/MCP, Browser, or release behavior.

## Native architecture rules

- New Browser behavior should use TL Studio-owned `/local/*` product domains.
- Model connection definitions, discovery, credentials, and direct model execution belong to TL Studio.
- Sessions, Questions, Permissions, and semantic Events belong to TL Studio.
- Built-in Tool execution should reuse Project filesystem/Search/process/Permission infrastructure.
- Plugin/MCP tools must continue through the TL Studio Tool Registry and Permission path.
- Secrets must stay out of ordinary JSON configuration and Browser storage.
- Monaco is an Editor engine, not a filesystem authority.
- Previewed Project code stays on a separate loopback origin from the privileged control server.
- Do not load Editor assets from a CDN.

## Plugin/MCP rules

The current Plugin contract is MCP over stdio.

Saving a Plugin must not start arbitrary local code. Enablement remains an explicit confirmed action.

Project/Global scoping, working-directory confinement, credential references, Tool discovery, and process cleanup must preserve the existing trust boundary.

Bundled Plugins must be version-pinned and declared through the release manifest; do not silently introduce a bundled executable.

## Account connection rule

The generic account adapter domain is part of TL Studio's internal product boundary. Public documentation describes only account behavior that exists in the stable `main` source.

## Release rules

`main` is the documentation source of truth for the public stable product. Stable npm publishing and release packaging are derived from the validated stable source.

Release/CI gates enforce the current TL Studio product architecture and validate production packaging.

## Documentation rules

The stable `main` source is the documentation source of truth.

Keep public language centered on **TL Studio** and document only behavior that exists in the current stable source.

Do not preserve obsolete architecture wording merely for historical continuity.
