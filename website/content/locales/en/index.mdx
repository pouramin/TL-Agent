TL Agent is a **local, standalone coding-agent workspace**. It gives you a dedicated browser environment for working with local projects, sessions, agents, models, tools, providers, file attachments, permissions, file changes, and project files without requiring an IDE.

## Product identity

TL Agent is the product you install and interact with. Project selection, sessions, provider settings, attachments, recovery, security, packaging, and the browser experience are all part of TL Agent.

```text
You
  ↓
TL Agent
  ├─ browser workspace
  ├─ project picker
  ├─ sessions / files / changes
  ├─ attachments + provider settings
  ├─ local security boundary
  └─ launcher + packaging
       ↓
Bundled agent runtime
       ↓
Models / providers / project tools
```

The bundled runtime is an internal execution layer. Normal use should feel like operating one product: **TL Agent**.

## What you can do

- choose a local project from the operating-system folder picker;
- create, rename, and delete sessions;
- choose an agent and model;
- attach images, PDFs, and text/code files by picker, drag/drop, or clipboard paste;
- add custom OpenAI-compatible, OpenAI Responses, or Anthropic-compatible providers from Settings;
- send prompts and follow live reasoning/tool activity;
- recover from retryable provider failures without losing existing file changes;
- approve or reject permission requests and answer interactive questions;
- inspect project files and per-session changes;
- interrupt an active run;
- personalize theme and UI font size;
- use the application without VS Code, JetBrains, Cursor, Docker, or a TL Agent cloud backend.

## Current stable release

**v0.2.0 is the first stable baseline of TL Agent.** The default npm launcher follows the stable `latest` channel:

```bash
npx --yes tl-agent
```

Experimental builds can continue on explicit prerelease channels such as `tl-agent@alpha` without changing the stable path.
